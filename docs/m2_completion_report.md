## Final browser flow

A real manhole image was analyzed by the M1.13 model. The browser then:

1. resolved location context
2. displayed unverified authority status
3. generated a complaint draft
4. edited the title and description
5. created a CVKI case
6. displayed the internal CVKI Reference ID
7. displayed `Submitted to CVKI`
8. displayed `External Government Submission: Not Submitted`
9. displayed follow-up guidance
10. retrieved the same case status

The edited title and description were preserved exactly by the backend case.
The genuine no-detection image displayed no complaint workflow.

## Known limitations

- Case storage is in-memory and data is lost on backend restart.
- No government portal submission or external complaint tracking exists.
- No authentication, notification, escalation, payment, or production database exists.
- Authority results remain `not_verified` when no authoritative evidence source is configured.
- Complaint drafts are deterministic rule-based templates, not generated by an NLP model.

## Explicitly not implemented yet

- MongoDB production persistence
- Government portal integration
- Government complaint submission
- External complaint tracking
- Authentication
- Notifications, SMS, WhatsApp, and email
- Automatic escalation
- NLP model training
- M3 work
